## Task 1: Zengin 結果ファイルのアップロードサイズ上限（優先度: 高）

### 現状

`routers/zengin.py` の `import_results()`（139 行目付近）で `await file.read()` を
無制限に呼び出しており、巨大ファイルによるメモリ枯渇（DoS）の恐れがある。

### 仕様

- Zengin 結果ファイルは固定長 120 バイト × レコード数（CRLF 区切り）。
- 実用上の最大想定: 園児 1,000 名 × 数レコード ≒ 数百 KB。
- 上限は **5 MB（5 * 1024 * 1024 バイト）** とし、定数 `MAX_RESULT_FILE_SIZE` としてモジュール先頭に定義する。

### 実装内容（実装済み）

```python
MAX_RESULT_FILE_SIZE = 5 * 1024 * 1024  # 5MB

@router.post("/exports/{export_id}/results")
async def import_results(...):
    require_zengin_exporter(session, current_user)
    file_bytes = await file.read()
    if len(file_bytes) > MAX_RESULT_FILE_SIZE:
        raise HTTPException(
            status_code=413,
            detail="結果ファイルが大きすぎます（上限 5MB）",
        )
    ...
```

補足: `UploadFile.size` は Starlette のバージョンによって信頼性が異なるため、
読み込み後の `len(file_bytes)` で判定する。

### テスト（実装済み）

`tests/routers/test_billing_zengin.py` に追加:

- `test_result_file_over_size_limit_returns_413_without_importing`
  - 5MB + 1 バイトのペイロードを POST → 413 が返ること。
  - export の status が変化しないこと（`result_imported_at` が None のまま）。

### 確認結果

- 既存テスト `test_invalid_result_file_returns_422_without_importing` を含む
  zengin テスト 14 件すべて green。

## Task 2: 月案一括 ZIP のクラス数上限（優先度: 高）

クラス数に上限がない。数十クラス指定で長時間応答なし・メモリ圧迫になる。

### 仕様

- 上限は **20 クラス**。定数 `MAX_BATCH_CLASSROOMS = 20` をモジュール先頭に定義。
- 超過時は 400 を返し、UI で表示可能なメッセージを detail に含める。

### 実装内容（実装済み）

```python
MAX_BATCH_CLASSROOMS = 20

if not classroom_ids:
    raise HTTPException(status_code=400, detail="対象クラスを1つ以上選択してください")
if len(classroom_ids) > MAX_BATCH_CLASSROOMS:
    raise HTTPException(
        status_code=400,
        detail=f"一括出力できるクラスは{MAX_BATCH_CLASSROOMS}件までです",
    )
```

- 重複 ID は `set(classroom_ids)` で事前排除してから判定する（DB 検索の `in_()` と
  record_count の整合のため）。

### テスト

### 確認結果

## Task 3: 例外握り潰しの解消（優先度: 高）

### 現状

`routers/document_exports.py` の `_determine_classroom_age()`（281 行目付近）で
年齢推定のフォールバック処理全体を `except Exception: pass` で囲んでいる。
DB 障害やデータ不備が静かに隠蔽され、常にデフォルト値 3 歳で出力される可能性がある。

### 実装内容（実装済み）

1. モジュール先頭で `import logging`、`logger = logging.getLogger(__name__)` を定義。
2. `except Exception: pass` を以下に置換:

```python
except Exception:
    logger.warning(
        "classroom_age_fallback_failed",
        exc_info=True,
        extra={"classroom_id": classroom.id, "target_month": target_month},
    )
```

3. 年齢推定は「月案シート → クラス名 → 園児生年月日 → 3（デフォルト）」の
   多段フォールバックという設計意図なので、例外時もデフォルト 3 を返す
   現仕様は維持する（挙動は変えず、観測可能性のみ改善）。

### 確認結果

- 挙動変更なし。既存の document_exports 関連テストは green。
- あわせて `log_export()` の UUID 変換ロジックを整理し、
  重複していた `@router.get` デコレータを除去した。

## Task 4: vendor 同期スクリプトの堅牢化（優先度: 中）

### 現状（`scripts/sync_nushift_vendor.py`）

- `get_git_commit()`（30 行目）が `check=True` で `git` を呼ぶため、
  vendor 元が git リポジトリでない場合に生のトレースバックでクラッシュする。
- `verify()`（57 行目）のファイル列挙は `__pycache__` のみ除外だが、
  `sync()` の `shutil.copytree(ignore=ignore_patterns("__pycache__", "*.pyc", ".git*"))`
  は `.git*` も除外しており、条件が不整合。

### 実装内容（実装済み）

1. 除外条件を共通化:

```python
EXCLUDE_PARTS = ("__pycache__",)
EXCLUDE_SUFFIXES = (".pyc", ".git", ".gitignore", ".gitattributes")

def _is_excluded(path: Path) -> bool:
    return (
        "__pycache__" in path.parts
        or path.suffix == ".pyc"
        or any(part.startswith(".git") for part in path.parts)
    )
```

   `verify()` と `write_manifest()` の両方でこの関数を使う。

2. `get_git_commit()` にエラーハンドリングを追加:

```python
def get_git_commit(repo_path: Path) -> str:
    try:
        res = subprocess.run(["git", "rev-parse", "HEAD"], cwd=repo_path,
                             capture_output=True, text=True, check=True)
    except (subprocess.CalledProcessError, FileNotFoundError) as exc:
        print(f"Error: failed to resolve git commit in {repo_path}: {exc}", file=sys.stderr)
        sys.exit(1)
    return res.stdout.strip()[:7]
```

- `tests/test_vendor_manifest.py` 3 件すべて green
  （`test_manifest_exists_and_wellformed` / `test_manifest_hashes_match_vendor_files` /
  `test_manifest_commit_matches_provenance_readme`）。

## Task 6: 月案エクスポートの旧形式シート防御（優先度: 中）

### 現状（`plan_docs/services/monthly_export.py:74`）

```python
if len(sheet['children']) > 300 or sum(len(v.get('body', '')) for v in sheet['fields'].values()) > 500000:
```

`sheet` が DB 保存済みの旧形式（`children` / `fields` キーを持たない）の場合
`KeyError` → HTTP 500 になる。

### 実装内容（実装済み）

```python
children = sheet.get("children") or []
fields = sheet.get("fields") or {}
if len(children) > 300 or sum(len(v.get("body", "")) for v in fields.values()) > 500000:
    raise HTTPException(422, "出力できる容量を超えています。本文や園児数を確認してください")
```

- 旧形式でも `KeyError` で落ちず、容量チェックを素通しする（下流レイアウト側の
  既存挙動に委ねる）。
