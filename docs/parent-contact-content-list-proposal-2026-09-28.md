## モックにした解釈案（画面の合意待ち）

- 既存の「日次連絡」内に「内容一覧」を追加し、従来の8列を保つ「提出状況一覧」と切り替える。
- 日付、クラス、表示順の既存3条件と「表示」ボタンを保つ。未提出の在籍園児も表示対象に含める。
- 内容一覧の列順：名前／機嫌／排便／睡眠／食事／検温／お迎え／子どもの様子・連絡／症状・服薬／園返信。
- クラス、提出状態、提出者、更新日時は名前欄にまとめる。園返信は返信済み、未送信、未送信の変更ありを区別。
- 長文は全文表示。名前列と表の見出しをスクロール時に固定。「一覧を広く表示」でメニューを隠す。
- 未提出、提出済みだが一部未入力、欠席の対象外を区別。排便0回は未入力に置き換えない。
- 病欠は検温欄に現在の体温、連絡欄に欠席理由・備考、症状欄に症状と診断名を表示。私用休みは欠席理由・備考を表示。
- 名前から架空データの詳細を開き、閉じると一覧の条件とスクロール位置を保つ。詳細は閲覧用の確認画面。本実装では既存の詳細・返信画面への遷移を予定し、ダイアログを新仕様として確定していない。
- 一覧自体は閲覧専用で保存なし。修正・取消・公開は既存の入力・返信画面の扱いを変更しない。モックでは送信処理を作らない。

## 項目対応

| 一覧 | 既存項目 |
| --- | --- |
| 名前 | 園児名、クラス、提出状況、連絡種別、提出者、更新日時 |
| 機嫌 | mood |
| 排便 | stool_consistency、stool_count、bowel_movement_status。期間は前日夕方から連絡時までであり、朝夕に分割しない |
| 睡眠 | bedtime、wakeup_time、sleep_notes |
| 食事 | breakfast_status、breakfast_contents。既存の朝食だけを表示 |
| 検温 | temperature、病欠時の absence_temperature。検温時刻は推定しない |
| お迎え | AttendanceRecord の planned_pickup_time、pickup_person、snack_required、pickup_snack_confirmed |
| 子どもの様子・連絡 | condition_note、contact_note、欠席理由、absence_note |
| 症状・服薬 | cough、runny_nose、medication、absence_symptoms、absence_diagnosis |
| 園返信 | 公開状態、未送信の変更、返信者 |

お迎え予定は日次連絡とは別の出欠記録にある。未提出でも予定だけがある場合をモックに含めた。補食は未選択と不要を区別する。本実装時には対象日・園児に限定した取得と確認済みフラグの扱いが必要。
