**B1 画面仕様（表示条件・遷移・保存タイミング・取消動作）**

- **解除ボタンの表示条件**: サイクル一覧の各行で `reopenable_export` が返る出力に対し、
  L0 は Zengin出力権限保持者に、L1 は admin に「取消して修正」を表示。
  L1 で申請済みの場合、申請者には「園長確認待ち（◯/◯ ◯:◯）」を非活性表示、
  admin には「確認する」ボタンを表示。
- **dialog の状態遷移**:
  1. `初期`: レベルバッジ（L0/L1/L2）+ dry-run 差額試算（「再作成で ◯円・△件 変わります」）
     + 定型理由5チェック+補足+未提出確認チェック。
  2. `L1申請`: 「この内容で園長に確認を依頼する」ボタン → 申請フラグ+理由を保存し、
     申請者には確認バナー。**解除はまだ実行しない**。
  3. `承認`: admin が同一 dialog を開くと申請理由・申請者・差額が表示され、
     差分（試算が申請時とずれた場合）を警告の上で実行。実行時に未提出確認チェックを
     **必ず再要求**（申請時のチェックを引き継がない）。
  4. `エラー`: 試算失敗・楽観ロック競合・権限不足を dialog 内にインライン表示
     （既存 `billing-reopen-error` の枠組みを流用）。
- **保存タイミング**: 申請フラグ・理由は申請POST時に即保存（下書きなし）。
  解除実行（`cancel_zengin_export_for_edit` + 監査ログ）は承認後の POST のみ。
- **取消動作**: 申請の取り消しは申請者/admin が一覧から1クリック（フラグを戻すのみ、
  監査ログに「申請取消」を記録）。解除実行後の取り消し（再オープンの再オープン）は存在しない。

### 移行・ロールバック（B1 / B4 の alembic）

- B1: `zengin_exports` に **nullable 列のみ追加**

  非表示になる安全側）。段階リリースは N2→N3/N4→N5→N6 のマイルストーン順で担保。

**`tests/test_billing_reopen_levels.py`（B1・統合）**

5. 銀行提出済み（L2）は従来どおり admin のみで解除可能・非admin は 403
6. dry-run 試算が実際の再計算結果と一致する
7. 定型理由「その他」で補足が空の場合はエラー
8. 既存の未提出確認チェック・500字制限・監査ログ形式が変わらない
9. 申請の取り消しがフラグを戻し、監査ログに「申請取消」を記録する
10. 複数 admin の同時承認で 2 件目が 409 になる
11. 承認 dialog で申請時の試算と現在の試算がずれている場合、差分警告が表示される

## （参考）フェーズA 作業パッケージ W1〜W5

### W1. 日次連絡フォームのレイヤー化（実装済み）

1. **前日値取得**: contact GET で `target_date - 1日` の `DailyContactEntry` を読み込み
   `previous_entry` としてテンプレートへ渡す。
2. **「前回の入力を反映」常設化**: 毎日表示。押下で前日値をフォームへ反映。
3. **レイヤー化**: 「前日のお世話」セクション（就寝・起床・排便・朝夕食）を `<details>` 折りたたみ。
   見出しに「変更がなければ開かなくて構いません」+未入力バッジ。
4. **緊急連絡先の 1 行サマリー化**: 変更なしは 1 行表示。変更 UI は「今日は変更する」で開く
   （`family_emergency.py` の revision/lock 機構は触らない）。
5. **お迎え「前回と同じ時刻」チップ**: 明示タップで設定。自動プリセットなし。
6. **送信確認バナー**: POST 成功時の `notice` に引き継ぎ文言（parent_portal.py:1678）。
7. **フォームバージョン**: `contact_layout_version` hidden（値 "2"）。v1/v2 両受理。
   検証ロジック（`validate_home_care` / `validate_meals` / 体温チェック / `contact_revision`
   楽観ロック / pickup 保存）は共通のまま変更しない。

### W2. 朝夕の食欲・献立の改善（実装済み）

1. **「よく食べた（いつもどおり）」ボタン**: 食欲「完食」を自動選択（選び直し可）。
2. **献立履歴チップ**: 過去 30 日の `extra_data` からユニークチップ（最大 8 個）。タップで追記。
3. **ラベル変更**: 「食べたもの（書かなくてOK）」。
4. **食欲スケール統一**: `APPETITES_V2`（home_care_details.py:6）。`validate_meals` は
   空欄/旧/新を受理。ラジオは新スケールのみ、表示は旧値もそのまま（無理な変換なし）。
5. **夕食リマインド通知**: 毎日 19:00（`dinner_reminder_time` で設定可）。
   未入力園児の保護者のみ。タップで `#meal-dinner` ディープリンク。
   保護者設定 `dinner_reminder_enabled`（初期オン）でオフ可能。
6. **用語の補足表示**: 園側返信と家庭入力が同一スケールになった旨を文脈ヘルプで案内。

### W3. 医療同意の引き継ぎ同意（実装済み）

1. **差分検出**: `parent_medical_service.diff_from_baseline`（`FIELDS` + `xray_answer`）。
2. **引き継ぎフロー**: 前年度 approved 値をプリセット。差分ゼロ+トグルオン → `approved` 直行、
   旧回答は `superseded`、`auto_approved` を保持。トグルオフ → 従来どおり `pending`。
   差分ありは常に従来フロー。
3. **園設定トグル**: `facility_settings_service.medical_consent_auto_approve`（初期 False）。
4. **園側 UI**: 自動承認分は「自動承認」バッジ表示、確認待ちバッジは変更あり提出のみカウント。
5. **不変の保証**: `revision` ハッシュ・409 競合制御・300 文字制限・`form_answers` 検証は変更しない。
