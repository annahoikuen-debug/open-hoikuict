# 児童記録 独自項目設定 確認用モック

仕様: `child_records/settings.py`、`child_records/router.py`

```powershell
venv/Scripts/python.exe -m http.server 8908 --bind 127.0.0.1 --directory tools/child-record-custom-field-preview
```

<http://127.0.0.1:8908/>

`index.html` をそのまま配信できる。**外部通信・本番 DB・送信処理なし。**  
入力内容は保存されない（ページ内の状態のみ）。

## 対象画面（画面1〜3）

| 画面 | 内容 |
| --- | --- |
| 1 独自項目一覧・並び替え | 現在の独自フィールド一覧。ドラッグ or ↑↓ ボタンで順序変更 |
| 2 追加・名称変更 | フォームでラベル入力→追加。既存フィールドのラベル編集（内部キーは変わらない） |
| 3 削除・確認ダイアログ | 削除対象を選択→「過去のレコードはどうなるか」確認→削除実行 |

## 確認用パネル

上部黒帯は確認専用で本番画面には表示されない。

- **画面**: 3画面を切り替える
- **状態を切り替えて試す**: フィールドなし / 初期3件 / 多数8件
- **内部キー表示**: `custom.UUID` 形式のキーを表示し、ラベル変更後も変わらないことを確認

## 技術的留意点（実装時に持ち越す）

- `new_custom_field_key()` が返す `custom.{uuid4()}` は不変。ラベル変更時も同一キー
- 設定保存 → `ChildRecordSettingVersion` の `version_no` インクリメント
- 削除後も既存レコードの `custom_values[key]` は JSON に残る（読み取り専用で表示）
- 独自フィールドは `observation_log.fields` に `system: false` として追記

## 確認観点（ユーザー試用時のチェックリスト）

- [ ] 追加したフィールドが一覧に表示される
- [ ] ラベルを変更しても内部キーが変わらない
- [ ] 並び替えが即時反映される
- [ ] 削除確認ダイアログが表示される
- [ ] 削除後、過去レコードへの影響について説明文が適切か
