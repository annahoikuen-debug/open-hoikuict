## 確認用パネル

上部の黒帯は確認専用で、本番の画面には表示されない。

- **画面**: 5画面を切り替える。サイドバーの「職員シフト」でも移動できる
- **状態を切り替えて試す**: 画面ごとに未入力／入力済み／一部入力／エラーを切り替える
- **入力を初期化**: 編集内容を破棄する

| 画面 | 選べる状態 |
| --- | --- |
| 1 登園予定時刻 | 入力済み / 未入力（全員が保育必要量区分に落ちる） / 一部入力（5名だけ既定値あり） / 閉園より後・開園より前・対象月外の例外日 |

## 業務ルール（2026-10-03）

### 1. 確定は園長の承認で完了する

画面5 の一番下に「ログインしている人」の切り替えがあります。

- **桐生 園長（園長）** → 確定できる
- **早乙女 主任（一般職員）** → 確定できない（作成・編集はできる）

BLOCKER があるときは**園長でも確定できません**。一般職員のときは、
「確定する（園長のみ）」と表示され、押せません。

### 2. 時間外労働は「案」の段階なので、毎日発生する前提で計算する

画面5 の「月次の時間外労働日数」は、**勤務日数すべて**を時間外労働日数として数えます。
5日勤務の職員なら月20日 정도になるので、「月5日・年6日」の枠を大幅に超えます。

これは**問題ではなく、前提からそうなる**ものです。枠の超過は**参考表示のみ**で、
確定を止めません。止めするのは**1日10時間超だけ**（労働基準法32条違反）です。

実際に時間外労働を入れた段階で、枠を BLOCKER にするかが変わります。

## データについて

`mock_data.js` の架空データのみ。実在する園児・職員・シフトではない。

- 職員30名（配置対象25名・配置対象外5名）。定員60名の園を想定
- 種別名・職員区分・配置基準14種は実物（`shiftai` の `domain.py` / `local_rules.py`）に合わせる
- **必要人数・シフト表・違反内容・人件費・労働時間はすべて仮値**であり、
  `shiftai` を実行した結果ではない
- シフト表と労働時間は職員ごとの契約（最早始業・最遅終業・1日契約時間・週最大出勤日数）から
  **決定論的に生成**する。ランダムではないため、日付を切り替えても同じ結果になる
- 実働時間は休憩を引かない。`shiftai` の payroll も同じ基準
  （`docs/07` T-05／`docs/09` NG-01 で意図と確認済み）
